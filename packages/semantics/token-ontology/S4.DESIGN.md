# S4 — the platform catalogue: the model and how it was reached

- Vocabulary: `definitions/dt.s4.ttl`
- Constraints: `definitions/dt.s4.shapes.ttl`
- JSON projection: `definitions/dt.s4.context.jsonld`

This file is the reasoning: what was tried, what killed each alternative, which
claims are measured and which are only argued. Numbers are from a fresh build of
`packages/tokens` and the graph in `data/`, 2026-09-07, and every one of them has
been recomputed by an independent reviewer.

---

## 1. What the stratum is

S1 records what was authored. S2 records what varies and where it attaches. S3
records what a token resolves to. None of them says what a *platform ships*.

S4 does, and there is **one catalogue per platform** — the platform is the
identity of the file, not a column inside it. The subject is a **variable and
every place it is declared**. On the web: 1,904 declarations over 1,156
variables and 31 conditions.

**Why recorded rather than derived.** Every byte the build emits is a function of
S1, S2 and the profile, so a smaller model is possible: record the *rules*, and
regenerate. That model was rejected for one reason — a rule cannot be queried. A
consumer asking *what can I use, and how* must get an answer from the graph, not
from running a generator. The catalogue is the only stratum that can answer it.

---

## 2. The orientations that failed

Recorded because a rejected option with its reason is what makes a decision
revisitable.

**Coverage** — one node per (symbol, platform) with a status. Blind to the 278
web variables no symbol produces. *"Is `typography.heading.1` available in CSS?"*
has no honest answer: it emits no variable of that name and six that explode
from it.

**Projection / artifact** — one node per emitted name. An inventory: it cannot
say whether a symbol *can* cross to a platform before that platform's output
exists.

**Capability** — model each platform's powers, infer coverage. Exceptions become
overrides on derived facts, and the capability vocabulary is a second modelling
project.

**Binding** — (slot × symbol × admitted families). The richest, and the only one
answering *"your usage is wrong here"*. Set aside because slots belong to the
anatomy. **Contested**: a review argued this was a dodge, since the warning needs
only facts S4 and S2 already hold. Recorded as unsettled, not closed.

**Expression** — model the grammar of what a consumer writes. Dies at the
platform boundary: Figma has no expressions.

**Derivation** — generate platform names from symbol names. Falsified by
measurement:

1. The rule is not dots-to-hyphens. `convertTokenIdToCssVar` kebab-cases each
   segment; dots-to-hyphens is the retired rule.
2. 204 variables ship a second, legacy name (`--color-focusRing` beside
   `--color-focus-ring`) and appear in no build artifact at all.
3. `--typography-heading-1` does not exist — that symbol emits six names whose
   ids are not symbols.

The lesson generalises: **this stratum records, it does not derive.** Recording
survives a naming change; deriving does not.

*Method note.* An earlier round measured against a `dist/` six days older than
the naming code, and one proof was circular — a flag edited two days earlier was
presented as a discovery. Both were caught by review. Every figure here is from a
fresh build and has been independently recomputed.

## 3. The rulings

Eight. Two arrived from adversarial review after the first six were drafted, and
(E) was rewritten after a second review found its first repair joined to nothing.

### (A) `dt:emits` holds the declared value verbatim, never normalised

*Alternative:* parse values into a structured form, as `dt:resolvesTo` does.

*Why it loses.* The regeneration law dies — printing every `dt:emits` under its
condition reproduces the output exactly, and that is the only completeness proof
available. A normalised catalogue prints something a rule *converts into* the
output, which is a derivation.

And some values have no form to normalise into:

```css
--hover--color-foreground-primary:
  oklch(from var(--modifier-color-foreground-primary, var(--color-foreground-primary))
        calc(l + var(--delta-hover-color-foreground-primary)) c h);
```

A relative colour carrying arithmetic over a variable. Normalising means minting
a computation vocabulary — a second modelling project disguised as a storage
decision.

*Cost:* "which declarations resolve to white" requires parsing.

### (B) A declaration is anonymous, but classed

*Alternative:* mint an IRI, most naturally from output file and line.

*Why it loses.* `(variable × condition)` already determines the declaration —
**verified unique across all 1,904** — so an IRI re-encodes what the triples say.

The file-and-line variant is worse. `--delta-hover-color-foreground-primary` is
declared at `modifiers.theme.css` lines 391, 413 and 432. Insert one line above
391 and all three identifiers change, along with every identifier below. Emission
order was made declarative precisely so a source reshuffle stops moving lines.

*Classed, though.* An earlier draft left declarations anonymous **and unclassed**,
which leaves nothing for a shape to target. `dt:ResolvedValue` is the precedent:
anonymous individuals, named class.

### (C) Conditions are minted from a sanitised slug, and shared

*Alternative:* carry the platform's expression on every declaration; or mint from
that expression directly.

*Why inlining loses.* 1,904 declarations over 31 conditions means each restated
~61 times, and `dt:selectsCoordinate` restated with it — turning a node lookup
over 31 into a string comparison over 1,904.

*Why minting from the selector loses.* It produces invalid IRIs. Measured:
selectors contain space, `(`, `)`, `*`, `:`, `@`. Spaces are illegal in an IRI.

*The rule.* Lowercase; strip leading `@ . :`; replace runs of non-alphanumerics
with `-`; trim; empty becomes `universal`. Join the at-rule path with `/`.

```
@layer ds.modifiers ▸ .success            → layer-ds-modifiers/success
@layer ds.surfaces  ▸ .surface .surface   → layer-ds-surfaces/surface-surface
@layer ds.states    ▸ *                   → layer-ds-states/universal
```

Verified across all 31: **no collisions**. The mint is lossy on purpose —
`.inProgress` slugs to `inprogress` — because the verbatim form lives on the
platform's own property. **It is lossy where CSS is not**: `.surface.surface`
and `.surface .surface` would slug identically. Safe today, guarded by law L2.

### (D) Structure inside a value is parsed, not stored beside it

*Alternative:* assert the ordered variables each declaration reads.

*Why it loses.* The interesting values are not flat lists:

```css
--disabled--color-text: color-mix(in oklch,
    var(--modifier-color-text, var(--surface-color-text, var(--color-text))) 34%,
    var(--surface-color-background, var(--color-background)));
```

Five variables **nested**, where the nesting is the fallback semantics. A flat
list loses which falls back to which; preserving it means a tree mirroring the
string — a second copy of one fact, with nothing to say which is right when they
disagree. Drift is not hypothetical: a hand-kept copy of a coverage flag is what
rendered disabled text black on black.

S3 ruled on this shape when it dropped `dt:projects`: the route is the single
fact.

*Scope, corrected.* (D) governs structure **inside** a value. It does not govern
the bridge — see (E). And it is not free: the closure law needs a parser, and the
language server's current one handles only a bare single `var()`.

### (E) The bridge is the variable's identity plus the declaration's position

*The defect it repairs.* All 1,072 resolved values in S3 are blank nodes, by
C.03's ruling that a value's identity is its (symbol × assignment) pair. A blank
node cannot be referenced from another document, so a `dt:delivers` edge ranging
over `dt:ResolvedValue` was **unwritable**. The first draft shipped an elegant
diagram of an impossible link.

*The first repair, and why it was wrong.* A `dt:Delivery` node on each
declaration stating (symbol, coordinates). Review found it joined to nothing for
175 declarations — every channel written under a modifier class — because S3
declines every non-mode position on purpose, and it restated the condition's
coordinate on every row. Two questions had been conflated: which **symbol** a
variable is, and which **value** a declaration puts on the platform.

*The repair that holds.* Identity lives on the **variable**: `dt:ofSymbol`. The
position comes from the **condition** (`dt:selectsCoordinate`) plus any extra
position the line carries (`dt:alsoAt`, for the dark half of a `light-dark()`).
The join is (ofSymbol × position) against S3's (forSymbol × coordinate*) — a
key, not a pointer. Verified: 0 duplicate keys in S3, and all 261 paired symbols
hold both positions.

*What the value's shape gates.* Not the join — the walk. Of 1,904 declarations,
746 are TERMINAL (a literal) and 1,158 REFERENCE another variable. A variable
with no symbol — a channel, a computed state — cannot join directly and follows
`dt:references` until it reaches one that can. `--modifier-color-text` under
`.success` references `--color-text-success`, which is `color.text.success`,
which S3 holds at the default position. One hop, then join.

*Alternative rejected:* widen S3 to materialise every modifier position. It
reverses a ruling in a published stratum and shapes S3 by what CSS happens to
emit under class selectors. It can be added later on top of this; the reverse
is not true.

**Superseded in part, 2026-09-10 (ADR J, AT.05/AT.06), for channel variables
only.** Two statements above no longer hold as written.

*"One hop, then join" is no longer the only mechanism.* The 25 channel
variables whose channel S2's coverage predicts now carry `dt:ofSymbol` naming
that channel symbol, so they join by the same key as every other variable. The
walk stays, and is what the remaining cases use: the three channels the build
emits without coverage behind them, and the computed state variables. The
reason is that the anatomy needs something to bind to — a slot reads
`--modifier-color-text` directly, and a rule inside this stratum is not a
symbol an anatomy can name.

*S3's decline of non-mode positions is lifted for channels, and only for
channels.* A channel's whole content is another symbol's value under an active
coordinate, so a channel with no such position would be a symbol with no value
anywhere. S3 now holds one node per (channel × coordinate) pair — **165** —
each carrying `dt:derivedFrom` and neither a value nor a `dt:resolutionChain`.
No other symbol gains a position, so the alternative this ruling rejected —
materialise every modifier position for every symbol — is still rejected. What
is taken instead is the narrow case where the platform is already provisioning
the value.

*And the routing is read out of this stratum, not derived from names.* The
naming rule that suggests itself — `modifier.X` at coordinate C is the symbol
`X.<last segment of C>` — was measured against the 175 channel declarations
here: right 102 times, wrong 73, and it invents symbols the build never emits.
`dt:references` is right 175 times. That is the strongest evidence yet for §2's
lesson, which said the same thing about names one stratum down.

**Superseded again, 2026-09-10, on the owner's instruction: a derived value
carries no value.** The first landing of the above materialised each pair twice
— once per mode — and each of the 330 nodes carried a `dt:resolvesTo`
**byte-identical** to its target symbol's value at the same mode. All 330 of
330, measured: **19,311 bytes** of duplicated JSON literal — 30,201 bytes with
the predicate and datatype that carried them — over 2,477 lines of
`data/s3.ttl` that said nothing the graph did not already hold, with drift the
only thing they could ever come to say.

*What replaced it.* A channel's node keeps `dt:forSymbol`, the coordinate its
declaration selects, and `dt:derivedFrom`, and drops `dt:resolvesTo`. A
consumer reads the value by following `derivedFrom` one hop to the target
symbol and taking THAT symbol's own value at whatever mode it wants — so the
target's dark value is the channel's dark value by construction, and drift is
impossible rather than merely unlikely.

*And then the mode coordinate went too, halving the node count.* With no value
on the node the routing is mode-independent: `modifier.color.text` at
`anticipation.constructive` routes to `color.text.constructive` in either mode.
The precondition was measured, not assumed — **0 of the 175 channel
declarations carry `dt:alsoAt`**, and **0** (channel × coordinate) pairs route
to more than one symbol — so no channel's routing differs by mode and one node
answers both. 330 nodes became 165; `data/s3.ttl` fell from 9,299 lines to
7,830 and from 448,277 bytes to 380,480, a saving of **67,797 bytes**.
Expressivity is unchanged: every value obtainable before is obtainable now, in
one hop.

*The invariant this pins, and why it is written down at all.* **A derived
routing carries exactly the coordinates its own declaration selects, never a
product of families.** Nine families offer 36 coordinates between them; nothing
in the graph would stop a future build materialising their product, and a
materialised cross-product explodes. Today's count is linear in S4's channel
declarations, and it must stay that way. `dt.ttl` carries the invariant on
`dt:ResolvedValue`; `populate.test.ts` asserts it — every routing carries
exactly one coordinate, and never a mode — so a row gaining a second is a red
bar and not a bigger file nobody reads.

*The shape now forbids the duplication rather than tolerating it.*
`dt:ResolvedValueShape`'s `dt:resolvesTo` moved out of an unconditional
`sh:minCount 1` and into the `sh:xone`'s two branches: a **selected** value
must carry both its `dt:resolutionChain` and its `dt:resolvesTo`; a **derived**
value must carry its `dt:derivedFrom` and `sh:maxCount 0` on both the other
two. The branches now exclude each other in both directions, so a node
carrying all three fails — which the old single-property `sh:xone` also caught,
and this keeps. No new vocabulary: the edit is inside existing terms.

### (F) `dt:at` is kept — the emitted location is recorded

*Alternative:* drop it, reach the location through the delivery.

*Why it loses.* It assumes every variable has a token behind it. **278 do not** —
204 legacy aliases with no artifact entry, plus 74 computed states and resets
(the two sets are disjoint; verified). For those, the delivery leads nowhere.

*Stronger than first argued.* Regeneration needs it too: one condition spans
three output files (`:root` under `@layer ds.modifiers` appears in spacing, theme
and typography), so grouping by condition cannot recover file boundaries without
it.

*Open:* `"file:line"` packs two facts into one string, which is the separator
magic C.03 rejected elsewhere. Left as one field for now; a reviewer flagged it.

### (G) The shared core is closed; platforms extend in their own namespace

*Alternative, and the one this replaces:* platform terms attach only to
`dt:Condition`.

*Why that loses.* Contradicted by the first platform we would add. Figma's
`Variable` carries `codeSyntax`, `scopes` and `key` — on the variable, not on any
condition. The rule was dead on arrival, and review killed it before a line of
Figma data existed.

*The rule.* The shared core is **closed**: its terms mean the same thing on every
platform and no platform may redefine them. A platform may add terms on any
class, in its own namespace — `dt-web:selector`, `dt-figma:codeSyntax`. The
boundary is **namespacing, not placement**.

*The law:* a cross-platform query must never need a namespaced term.

### (H) The build produces this stratum, not the populator

*Alternative:* the populator produces it, as it produces S1, S2 and S3.

*Why it loses.* The populator reads authored source. It cannot know what a
platform emitted — variable names, selectors, output locations, which variables
are machinery, which rule computed a derived value. The emitter knows all of it,
and already carries 1,700 declaration records.

*What it inverts, plainly.* For three strata the build is a **consumer** of the
graph; for this one it is the **producer**. Not accidental: S1–S3 describe what
was authored and what it means, knowable from source; S4 describes what was
shipped, knowable only from shipping.

*The consequence the build must absorb.* It works in resolver-**axis** names
while the graph names coordinates by **family**, and they diverge: the axis
`theme` encodes the family `mode`. A build minting `dt:coordinate.theme.dark`
would emit an IRI resolving to nothing — silently, for the largest family in the
system. Seven of eight axes agree; one does not. The mapping belongs in
`contracts/`, which the build already reads, and law L4 asserts it.

*The serialisation.* JSON-LD: one artifact readable as JSON by the language
server and as RDF by the graph server, so there is no second copy to drift.
Pragma ingests `.ttl` only, so a mechanical conversion produces the Turtle it
reads — nobody authors that file, so it cannot disagree with its input.

## 4. The two edges

S4 reaches the rest of the model through exactly two properties, because each
stratum already bridges to the one beneath it. S4 does not know S1 exists.

```
S4   --modifier-color-text  under .success
      │                                  │
      │ dt:delivers ── WHAT              │ dt:selectsCoordinate ── WHEN
      │   ofSymbol · atCoordinate        │
      ▼   (a join, not a pointer)        ▼
S3   resolved value                     S2  coordinate.criticality.success
      │  dt:resolvesTo                       │  dt:family → criticality
      │  dt:resolutionChain                  │  contract → dt:level.local
      ▼                                      ▼
S1   #color.text.success.$root              ds:  the design system's modifier
      description · inFile · tokenType
```

Variables that deliver nothing reach the strata through `dt:computedFrom` until
they land on one that does.

## 5. Laws — first run, 2026-09-08

Cardinality and typing are in `dt.s4.shapes.ttl`. Six laws need more than SHACL,
and `src/catalogue.ts` executes them. First generation of `data/s4.web.ttl`:
18,648 triples · 1,156 variables · 31 conditions · 1,904 declarations ·
byte-identical across runs.

| | | Result |
|---|---|---|
| **L1** | Regeneration: every declaration recorded, verbatim, under its condition | 1,904 of 1,904 recorded across 11 files. **3 foreign declarations** (`color-scheme`) have no term. Byte-level reproduction needs a serialiser and is not yet run |
| **L2** | No two conditions share a minted IRI | 31 of 31 distinct |
| **L3** | (symbol × position) matches exactly one resolved value, or is a position S3 declines | **matched 1,204 · declined 0 · missing 0.** Every variable with a real symbol joins at every position it declares, dark halves included. 961 declarations have no symbol to join on |
| **L4** | Every coordinate named exists in S2 | 23 named, 0 unknown. The `theme`/`mode` divergence did not bite because coordinates are read from S2's `encodes` edges, not minted from axis names |
| **L5** | Every referenced variable is in the catalogue | 0 dangling |
| **L6** | Every variable reaches one with a symbol | **29 do not**: 16 `--delta-*` literals, 13 typography slots |

*Second run, 2026-09-10, after the channel bridge.* L3 matched **1,369** and
no-symbol fell to **796** — the same 165 declarations, moved from one column to
the other by the 25 channels gaining `dt:ofSymbol` and S3 gaining their
positions. Declined and missing stay 0. The others are unchanged, L6 included:
delta 16, typography 13, twins 0, other 0.

*Third run, same day, after the derived values lost their copies.* **Every law
is unmoved** — L1 1,904/1,904 over 11 files, L2 31/31, L3 matched 1,369 ·
declined 0 · missing 0 · no-symbol 796 · phantoms 187, L4 23 named / 0 unknown,
L5 0 dangling, L6 29 in the same four buckets. That the bridge law does not
move is the point worth stating: L3 joins on (ofSymbol × the condition's
coordinates), and a channel node still holds the coordinate its condition
selects. Dropping the mode coordinate cost the join nothing, because no channel
declaration was ever matched against a mode position — `dt:alsoAt` appears on
261 declarations, none of them a channel's.

The laws are now a test (`src/catalogue.test.ts`) rather than a run recorded
here. L3, L4 and L5 are pinned at zero; L6's accepted 29 is pinned **per
population**, the two zero buckets included, because a new orphan in either
known group is what there is to catch and a single total would absorb it.

Two findings the laws produced that argument had not:

- **The bridge is clean.** `declined 0` means no variable with a symbol was ever
  emitted at a position S3 refuses — the fear behind option A (widen S3) had no
  instance in the data.
- **The 16 deltas are orphaned.** `--delta-hover-color-foreground-primary: 0.19`
  is a literal with no symbol and no reference, yet it is the value of
  `number.lightness.foreground.primary.hover.onLight`. The emitter baked the
  number and dropped the link. The catalogue cannot see it; the producer must
  say it.

And one count that matched a prediction exactly: **187 artifact ids are not
symbols** — the typography slots, PRA-157. The generator names no symbol that
does not exist in S1, so these carry no `dt:ofSymbol` and are reported as
phantoms rather than emitted as dangling IRIs.

## 7. Standing

**The stratum has been generated and confronted with data.** `data/s4.web.ttl`
exists, is deterministic, parses, and passes the package's parse and
vocabulary-closure gates alongside S1–S3 (31 tests). The six laws have run once;
their results are in §5. The producer is `src/catalogue.ts`, reading the build's
output — the script-first stand-in for ruling (H), not the emitter itself.

Not yet done, each with its trigger:

- **Byte-level regeneration (L1 proper)** — needs a serialiser and a term for
  `color-scheme`. Trigger: the emitter producing the catalogue natively.
- **The emitter as producer** — moving the generation into the plugin, emitting
  JSON-LD, converting to Turtle for pragma, and fixing the plugin's
  per-variable `derivedFrom` at source. Trigger: this script having taught us
  what the model gets wrong, which it now has.
- **A SHACL engine** — nothing runs the shapes; the existing `dt.shapes.ttl`
  has the same standing. Trigger: a second catalogue, when cardinalities start
  to matter across platforms.
- **The dark media query's coordinate** — left absent, flagged. A ruling.
- **The 16 orphaned deltas** — the producer must link them to their
  `number.*` symbols. A producer fix.
- **PRA-157** — typography composites. **PRA-158** — the anatomy connection.
- **The binding question — settled.** The anatomy binds each style key to one
  symbol and never narrows which families may speak. A component that must
  escape a family (a toast that must not follow surface nesting) is served by
  a **coordinate the algebra provides** — the `modal` surface, whose resets send
  every nested `--surface-*` back to the unmodified value — not by a property
  on the binding. Variation stays entirely in the algebra; a need no coordinate
  serves is a request for a new coordinate. Recorded on PRA-158.
